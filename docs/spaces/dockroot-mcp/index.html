dockroot-mcp

Virtual docker root for AI agents. Read-only power over a compose stack — without host root. Companion to Tabby Tavern 2.0, not a Tabby service.

Tabby lab tour Connectivity skill

DIAGNOSE. NEVER DESTROY. NO START / STOP / RM / EXEC.

WHY THIS EXISTS

Agents get asked “why is Open WebUI broken?” Without docker access they invent commands. With dockroot they list containers, read logs, inspect env/mounts, watch CPU/memory, and see networks — then answer from evidence.

Tools: docker_ps · docker_logs · docker_inspect · docker_stats · docker_networks plus the tavern connectivity toolkit (status, self_check, wire, rediscover, models, chat).

SECURITY MODEL

Read-only by design. Opt-in socket mount. Internal only — socket access is still powerful; do not publish this port. No socket mount, no docker access; the server reports that honestly.

HOW IT RELATES TO TABBY

Tabby Tavern 2.0 already runs MCPO at :8001 with FastMCP stack tools. Dockroot is the optional “see the Docker daemon” add-on — a different job than MCPO’s TabbyAPI/Ollama/SearXNG tools.

Live lab note (2026-08-25)

On LightBringer, ~/dockroot is a local recipe/MCP helper (tavern.sh, tavern_mcp.py, discover.py, recipes.py). It is not running as a container right now. This Space documents the companion; it is not a live docker socket.

DROP-IN SHAPE

services:
  dockroot:
    image: jpanasuk/dockroot-mcp:latest
    container_name: dockroot
    restart: unless-stopped
    networks: [ai-network]
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock

Wire through Hermes stdio or add a second MCPO mcpServers entry. Keep Tabby’s existing host-master server — empty configs crash MCPO.
