dockroot-mcp

Virtual docker root for the Independent AI Lab. Read-only power over compose — without host root. Part of Tabby Tavern 2.0, alongside MCPO’s seven stack tools.

Lab tour Connectivity skill

DIAGNOSE. NEVER DESTROY. NO START / STOP / RM / EXEC.

WHY THIS EXISTS

Agents get asked “why is Open WebUI broken?” Without docker access they invent commands. With dockroot they list containers, read logs, inspect env/mounts, watch CPU/memory, and see networks — then answer from evidence. That matters on LightBringer, where Tabby compose and llama.cpp are both the lab and must not both grab the 4070.

Tools: docker_ps · docker_logs · docker_inspect · docker_stats · docker_networks plus the tavern connectivity toolkit (status, self_check, wire, rediscover, models, chat).

SECURITY MODEL

Read-only by design. Opt-in socket mount. Internal only — socket access is still powerful; do not publish this port. No socket mount, no docker access; the server reports that honestly.

ON LIGHTBRINGER

Tabby Tavern 2.0 already runs MCPO at :8001 with FastMCP tools for TabbyAPI / Ollama / SearXNG. Dockroot is the “see the Docker daemon” layer — a different job.

Live lab (2026-08-25). ~/dockroot is a local recipe helper (tavern.sh, tavern_mcp.py, discover.py, recipes.py). It is not running as a container right now. This Space documents it; it is not a live docker socket. Do not bounce qwen38-llama-server from an agent with write access — dockroot stays read-only on purpose.

DROP-IN SHAPE

services:
  dockroot:
    image: jpanasuk/dockroot-mcp:latest
    container_name: dockroot
    restart: unless-stopped
    networks: [ai-network]
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock

Wire through Hermes stdio or add a second MCPO mcpServers entry. Keep Tabby’s existing host-master server — empty configs crash MCPO.
