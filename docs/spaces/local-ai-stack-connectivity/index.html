SERVICE NAME, NOT LOCALHOST. PATH IS /v1. MODEL ID IS EXACT.

CONNECTION RULE

Wire any OpenAI-compatible UI to an engine:
  1. Path is always /v1 → http://<host>:<port>/v1. Never /api/v1. Never put /v1/chat/completions in the base URL.
  2. Host is the in-network service name, not localhost — when the caller is itself a container.
  3. Host is loopback when the caller is on the host (Continue, a browser, Grok).
  4. Model is the exact served id (ask /v1/models).
  5. If the engine has auth, pass its API key. Do not “fix” a 401 by changing the host.

Two compose files, one GPU. They do not share a Docker network. Taproot WebUI (:3001) talks to llama.cpp through the host gateway. Tabby Open WebUI (:3000) talks to TabbyAPI/Ollama when that compose is up. One 4070 cannot run Tabby GPU services and llama.cpp at the same time.

PITFALLS ALREADY PAID FOR

  • Two heavy engines on a 12 GB card: the second CUDA alloc can block forever. Tabby GPU stays down while llama.cpp is resident.
  • Ollama global 64K context → huge KV cache → 8B weights pushed to CPU. Use flash-attn + q8_0 KV.
  • TabbyAPI dropped EXL2. Point model_name at an EXL3 directory.
  • Empty MCPO mcpServers: {} crashes the proxy.
  • SillyTavern refuses 0.0.0.0 without basicAuthMode: true.
  • SearXNG defaults to HTML-only; MCPO + RAG need json.
  • Recreating the llama service bounces the live qwen38-llama-server (yaml wants taproot-qwen).
