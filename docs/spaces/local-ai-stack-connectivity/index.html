SERVICE NAME, NOT LOCALHOST. PATH IS /v1. MODEL ID IS EXACT.

CONNECTION RULE

Wire any OpenAI-compatible UI to an engine:
  1. Path is always /v1 → http://<host>:<port>/v1. Never /api/v1. Never put /v1/chat/completions in the base URL.
  2. Host is the in-network service name, not localhost. Inside Docker, localhost is the container you are in.
  3. Model is the exact served id (ask /v1/models), not the word “ollama” or “llama.”
  4. If the engine has auth, pass its API key. Do not “fix” a 401 by changing the host.

Two stacks, two networks

Tabby Tavern 2.0 and Taproot do not share a Docker network. Do not point Tabby Open WebUI (:3000) at llama.cpp, and do not point Taproot WebUI (:3001) at TabbyAPI. Continue on the host talks to http://127.0.0.1:1234/v1 because Continue is not inside either compose.

PITFALLS ALREADY PAID FOR

  • Two heavy engines on a 12 GB card: the second CUDA alloc can block forever instead of erroring. Free VRAM first. Tabby GPU stays down while llama.cpp is resident.
  • Ollama global 64K context → huge KV cache → 8B weights pushed to CPU. Use flash-attn + q8_0 KV instead.
  • TabbyAPI current images dropped EXL2. Point model_name at an EXL3 directory.
  • Empty MCPO mcpServers: {} crashes the proxy. Keep at least one server.
  • SillyTavern refuses 0.0.0.0 without basicAuthMode: true.
  • SearXNG defaults to HTML-only; MCPO + Open WebUI RAG need json in search.formats.
