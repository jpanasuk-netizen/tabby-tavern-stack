THE PROBLEM

Chat, search, and inference are rented as separate SaaS products. Prompts leave the network. Keys rot. A 12 GB workstation can already run a private stack — if someone will compose it, document the failure modes, and ship character cards plus tools instead of a slide deck.

THE SOLUTION — TABBY TAVERN v2.0.0

A containerized private lab on Linux or Windows WSL2. Published as a Hugging Face model card and a tagged GitHub release. Weights and live keys stay off the public tree. You download EXL3/GGUF yourself and generate your own API keys.

:8080

Private metasearch with JSON enabled for MCPO and Open WebUI RAG. No tracking SaaS.

:8001

MCPO · FastMCP

Seven stack tools as OpenAPI: list/chat TabbyAPI and Ollama, pull models, health, SearXNG search. Docs at /docs.

Optional overlay, not core: docker-compose.starter.yml can add a browser IDE, vector DBs, and extra chat UIs on the same ai-network. It is not required to run the six-service lab, and it is not counted in the “6” above.

WHAT THE LAB ACTUALLY MEASURED

  • EXL3 chat on Llama-3.1-8B Instruct 6.0bpw, RTX 4070: ~53 tok/s processing in the 24/24 check pass.
  • VRAM: ~8 GB for that EXL3 pack + 8-bit cache; ~4 GB left for a small GGUF if you keep both loaded.
  • Decode telemetry in local_grid_suite: ~27× uplift after GPU routing on that run series. Single-box lab numbers, not a product SLA.

WHAT THIS MEANS

  • Own the path: compose, Dockerfiles, configs, character cards, and MCP tools are in the public repo. Weights you download. Keys you generate.
  • Data stays on the box: chat UIs, search, and inference never require a cloud API for the core loop.
  • WSL2 is documented, not hand-waved: NVIDIA toolkit repo line, libcuda.so linker fix, EXL2-dropped error, host-Ollama port clash.
  • Cards are first-class: SillyTavern PNG cards ship in-tree. Import them; do not commit chats or secrets.
